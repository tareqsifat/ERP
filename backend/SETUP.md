# Backend Setup

This backend was built in a sandboxed cloud environment that could reach
GitHub and npm, but **could not reach Packagist/getcomposer.org** — so
every file here was hand-written and `php -l`-linted, but `composer
install` has never actually been run against it. Follow these steps on a
machine with normal internet access (your own machine, a VPS, Codespaces,
etc.) to bring it up for the first time.

## 1. Install PHP dependencies

```bash
cd backend
composer install
```

Requires PHP ^8.3 with the `openssl`, `json`, `mbstring`, `pdo_mysql`,
`bcmath` extensions (all standard on most PHP installs). `bcmath` is used
by the arbitrary-precision decimal math in Modules/RawMaterial's stock
ledger and PO receiving (`bcadd`/`bcsub`/`bccomp`/`bcmul`) — quantities
there use 3 decimal places and float arithmetic isn't precise enough to
trust for stock math.

## 2. Environment

```bash
cp .env.example .env
php artisan key:generate
```

Edit `.env`: set `DB_DATABASE` / `DB_USERNAME` / `DB_PASSWORD` for a
MySQL 8+ database (sdd.md §1 — InnoDB, utf8mb4). Create the database
first:

```sql
CREATE DATABASE garments_erp CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

## 3. Passport

```bash
php artisan migrate
php artisan passport:keys
php artisan passport:client --password --name="Garments ERP SPA"
```

The last command prints a **Client ID** and **Client Secret** — put both
into `.env`:

```
PASSPORT_PASSWORD_GRANT_CLIENT_ID=<the id>
PASSPORT_PASSWORD_GRANT_CLIENT_SECRET=<the secret>
```

This client secret is used **server-side only**
(`Modules/Auth/App/Http/Controllers/AuthController.php`) — it never
ships to the frontend. See sdd.md §4 and that controller's docblock for
why the SPA doesn't call `/oauth/token` directly.

## 4. Seed roles, permissions, and the first Admin user

```bash
php artisan db:seed
```

This runs, in order: `PermissionSeeder` → `RoleSeeder` →
`AdminUserSeeder` → `LocationSeeder` → `SettingSeeder` →
`DemoDataSeeder`.

The admin seeder **generates a random password and prints it once** —
copy it immediately, it is not stored anywhere in plaintext.
`ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` env vars override the
defaults if you want a specific login for local dev. See failed_doc.md
§8/§10 for why there's no fixed default password.

`DemoDataSeeder` seeds a full, connected set of realistic-looking demo
data (see `../user_usage_guide.md`) — one demo user per role, sample
parties/raw materials/orders, and a complete Order → Booking → Cutting
→ Sewing → QC → Finished Goods → Stock Transfer → Shipment chain, plus
subcontract, accounting, and HRM cycles. It refuses to run in
`APP_ENV=production` unless `DEMO_SEED_FORCE=1` is set — for a real
client deployment, either leave it out entirely (run
`php artisan db:seed --class=PermissionSeeder` etc. individually,
skipping `DemoDataSeeder`) or just don't set `DEMO_SEED_FORCE` and let
it self-skip.

## 5. Run it

```bash
php artisan serve
curl -s http://127.0.0.1:8000/api/v1/health
```

Should return `{"data":{"status":"ok","service":"garments-erp-api",...}}`.

## 6. Run the tests

```bash
composer test
# or: php artisan test
```

`tests/Pest.php` auto-generates a Passport RSA key pair on first run if
`storage/oauth-private.key` doesn't exist yet — no manual step needed for
tests specifically (step 3's `passport:keys` is still required for the
actual running app).

## Module generator note

`config/modules.php` has `stubs.enabled` off — every module in
`Modules/` was hand-authored to match `nwidart/laravel-modules`'
real conventions (verified against that package's actual source), not
generated by `php artisan module:make`. Running that command for a
*new* module after this point will work normally and match the existing
modules' structure.
